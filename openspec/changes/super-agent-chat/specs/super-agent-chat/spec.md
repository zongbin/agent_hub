# Spec Delta

## Purpose

提供超级智能体的对话能力：用户以自然语言提交复杂任务，系统以流式事件推送智能体的分步执行过程与最终结果，并保留多轮对话上下文以支持连续追问。

## ADDED Requirements

### Requirement: 智能体对话入口
系统 SHALL 提供一个对话入口，接收用户任务描述与可选的会话标识，以服务端事件流（Server-Sent Events）返回执行过程与结果。

#### Scenario: 提交任务描述
- **WHEN** 用户提交非空的任务描述且未指定会话标识
- **THEN** 系统新建会话并开始执行，返回 200 与 `text/event-stream` 响应

#### Scenario: 任务描述为空
- **WHEN** 用户提交空白的任务描述
- **THEN** 系统返回 400，提示"任务描述不能为空"，不建立 SSE 连接

#### Scenario: 任务描述超长
- **WHEN** 用户提交的任务描述长度超过系统上限
- **THEN** 系统返回 400，提示任务描述长度超限，不建立 SSE 连接

### Requirement: 执行过程事件流
系统 SHALL 以结构化事件推送智能体的分步执行过程，事件类型 SHALL 取自 `agent.step.start`、`agent.step.progress`、`agent.step.complete`、`agent.complete`、`agent.error`。

#### Scenario: 步骤开始
- **WHEN** 智能体开始执行第 N 步
- **THEN** 系统推送 `agent.step.start` 事件，数据包含步骤序号与步骤名称

#### Scenario: 步骤进展
- **WHEN** 智能体在第 N 步产生思考内容或发起工具调用
- **THEN** 系统推送 `agent.step.progress` 事件，数据包含步骤序号与进展描述

#### Scenario: 步骤完成
- **WHEN** 第 N 步的工具调用执行完毕
- **THEN** 系统推送 `agent.step.complete` 事件，数据包含步骤序号与工具执行结果

#### Scenario: 全部步骤完成
- **WHEN** 智能体完成全部步骤并产出最终结果
- **THEN** 系统推送 `agent.complete` 事件，数据包含最终结果

#### Scenario: 执行过程出错
- **WHEN** 智能体执行过程中发生异常
- **THEN** 系统推送 `agent.error` 事件，数据包含错误描述，并结束事件流

#### Scenario: 事件数据格式
- **WHEN** 系统推送任一执行事件
- **THEN** 事件数据为 JSON 对象，且携带事件类型标识供前端区分处理

### Requirement: 鉴权与用户上下文
系统 SHALL 对对话入口执行与系统其余受保护接口一致的 JWT 校验，并将当前登录用户标识作为运行上下文传递给智能体服务。

#### Scenario: 未携带令牌访问
- **WHEN** 客户端未携带有效令牌请求对话入口
- **THEN** 系统返回 401，不建立 SSE 连接

#### Scenario: 携带有效令牌访问
- **WHEN** 客户端携带有效令牌请求对话入口
- **THEN** 系统放行请求，并以该令牌的登录用户作为运行上下文

#### Scenario: 越权访问被拒绝
- **WHEN** 当前登录用户的角色不具备调用对话入口的权限
- **THEN** 系统返回 403，记录拒绝审计日志，且不建立 SSE 连接

### Requirement: 会话历史管理
系统 SHALL 按登录用户隔离存储智能体会话及其消息，并提供会话列表、消息查询与删除能力。

#### Scenario: 列出会话
- **WHEN** 用户请求会话列表
- **THEN** 系统返回且仅返回该用户的会话，按最近更新时间倒序排列

#### Scenario: 查询会话消息
- **WHEN** 用户请求指定会话的消息列表
- **THEN** 系统返回该会话的消息，按发生顺序排列

#### Scenario: 访问他人会话
- **WHEN** 用户请求一个不属于自己且不存在的会话标识
- **THEN** 系统返回 404，提示会话不存在

#### Scenario: 删除会话
- **WHEN** 用户删除属于自己的会话
- **THEN** 系统删除该会话及其全部消息，返回成功响应

### Requirement: 多轮对话上下文
系统 SHALL 在同一会话的后续请求中回填历史对话内容，使智能体能够理解并回应追问。

#### Scenario: 携带会话标识继续对话
- **WHEN** 用户在同一会话中提交新的任务描述
- **THEN** 系统在执行前把该会话的历史对话内容作为上下文提供给智能体

#### Scenario: 历史上下文包含最终回答
- **WHEN** 系统回填某会话的历史上下文
- **THEN** 回填内容包含历史轮次的用户提问与智能体的最终回答

### Requirement: 前端超级智能体页面
系统 SHALL 提供独立于普通智能问答的超级智能体页面，调用对话入口并可视化分步执行过程。

#### Scenario: 页面入口
- **WHEN** 用户从导航进入"超级智能体"
- **THEN** 系统展示独立的超级智能体页面，包含会话列表、消息区与输入区，而非普通问答页面

#### Scenario: 步骤过程可视化
- **WHEN** 前端收到步骤类事件
- **THEN** 页面在对应助手消息下展示可展开的步骤列表，逐条呈现步骤序号、名称、进展与工具执行结果

#### Scenario: 最终结果展示
- **WHEN** 前端收到 `agent.complete` 事件
- **THEN** 页面结束流式等待状态并展示最终结果

#### Scenario: 错误展示
- **WHEN** 前端收到 `agent.error` 事件
- **THEN** 页面结束流式等待状态并展示错误提示

#### Scenario: 切换历史会话
- **WHEN** 用户在页面左侧选择某个历史会话
- **THEN** 页面加载该会话的消息并展示可继续追问的输入区
