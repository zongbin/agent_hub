## 一、产品定位

**一句话**：让企业散落各处的文档，能在一个入口用自然语言秒问秒答；复杂任务交给超级智能体自主调用工具执行。

### 解决的核心痛点

| 痛点 | 解决方案 | 当前状态 |
|------|---------|---------|
| 资料分散，找文档要翻 5 个地方 | 统一上传 + 语义检索 | ✅ 已上线 |
| 新人问重复问题，老员工被问烦 | 智能问答，7×24 在线 | ✅ 已上线 |
| 写报告/方案要东拼西凑 | 超级智能体自主调用工具 | ⚠️ 已上线，但**尚未接入知识库** |
| 文档版本混乱，不知道哪个最新 | 文档状态 + 密级 + 审计 | ⚠️ 部分落地（版本检测未做） |
| 操作不合规，事后无法追溯 | 审计日志 | ⚠️ 部分落地（覆盖范围窄） |

## 二、产品架构

```
┌─────────────────────────────────────────────────────┐
│                  智知 AgentHub                       │
│                                                     │
│  ┌─────────┐  ┌──────────┐  ┌──────────────────┐   │
│  │ 知识库   │  │ 智能问答  │  │  超级智能体       │   │
│  │ (上传/   │  │ (RAG     │  │  (ReAct 工具      │   │
│  │  索引)   │  │  检索)   │  │   调用循环)       │   │
│  └────┬────┘  └────┬─────┘  └────────┬─────────┘   │
│       │            │                  │             │
│  ┌────┴────────────┴──────────────────┴─────────┐   │
│  │              权限与安全层                      │   │
│  │         (角色 / 密级 / 文档级授权 / 审计)        │   │
│  └──────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────┘
```

三个模块共用同一套权限底座：**向量检索的权限过滤表达式直接下推到 pgvector**，
不在 Java 侧做「先全量召回再过滤」，因此不存在越权召回的中间态。

## 四、知识库模块

### 4.1 用户视角的能力

1. **上传**：拖拽或选择文件 → 填写标题、密级、标签 → 提交。
2. **异步索引**：文档立即返回并标记为「处理中」；后台完成解析 → 分块 → 向量化 → 摘要标签，回写「已就绪 / 分块数」。
3. **管理**：按关键字 / 密级 / 状态筛选，查看摘要、标签、分块原文，删除文档（软删除并同步清除向量，原子生效）。

### 4.2 产品规则

| 规则 | 当前实现 |
|------|---------|
| 密级默认值 | `INTERNAL`（内部）—— 新上传文档默认不对访客可见 |
| 支持格式 | docx / pdf / pptx / xlsx / txt / md（Apache Tika 自动识别） |
| 单文件上限 | 100 MB |
| 失败可见性 | 索引失败时文档标记「处理失败」并写入错误原因，前端可见，不静默消失 |
| LLM 不可用 | 降级：仍可解析、分块、向量化入库，仅缺摘要与标签 |
| 删除语义 | 软删除 + 同事务清理向量分块，杜绝「文档已删但仍能检索命中」 |

### 4.3 已知产品缺口

- 没有「重新索引」入口：改完源文件只能重新上传，会产生一条新记录。
- 没有文件内容指纹：同一份文件重复上传会产生重复文档与重复向量。
- 上传不校验扩展名白名单，非法格式要等到解析阶段才报失败（体验上应提前失败）。
- 原始文件不对外提供下载，智能体产物也无法回传。

## 五、智能问答模块

### 5.1 用户视角的能力

在「智能问答」页提问 → 流式看到答案 → 答案末尾列出**引用来源**（文档标题 + 分块序号）→ 点击跳转到对应文档的分块位置 → 可对答案点赞/点踩。

### 5.2 产品规则

| 规则 | 说明 |
|------|------|
| 上下文来源 | 只来自当前用户有权访问的知识库内容 |
| 引用可溯源 | 每个引用指向具体文档的具体分块，前端可直接定位 |
| 无答案不编造 | 检索为空时提示「知识库中未检索到与问题相关的资料」 |
| 越权不泄露 | 无权限文档在**召回阶段**即被过滤，不会进入提示词 |
| 多轮记忆 | 会话历史存 PostgreSQL，保留最近 10 条回灌上下文 |
| 内容安全 | 内置敏感词拦截（5 条词库），命中后直接拒绝、不调用模型 |
| 提示注入防护 | 系统提示词禁止「忽略指令」「扮演其他角色」，并禁止透露薪资等敏感信息 |

### 5.3 已知产品缺口

- **无自动路由**：用户需自己在「智能问答」和「超级智能体」两个入口之间选择，没有「简单问题秒回、复杂任务走 Agent」的自动判断（原设计中的 Task Router 未实现）。
- **引用颗粒度粗**：只到分块级，没有页码 / 章节路径。
- **反馈没有闭环**：`👍/👎` 落库后无统计看板，运营侧看不到满意度。
- **无重排序**：只靠相似度阈值过滤，长文档中的次优分块可能挤占上下文。
- **无跨库检索**：只检索本地上传的知识库，飞书 / 企微等外部源尚未接入。

## 六、超级智能体模块（核心亮点，也是最大缺口）

### 6.1 能力定义（按现状）

**智知 SuperAgent** 是一个基于 **ReAct（思考—行动）循环**的工具调用智能体。用户用自然语言描述一个任务，模型在最多 20 步内自行决定调用哪些工具、按什么顺序调用，直到调用终止工具或产出最终回答。

与早期 PRD 描述的 Plan-and-Execute（先出计划、用户可编辑）**不同**，当前实现没有「计划」这一概念：计划由模型在每一步隐式决定，用户看到的是**执行轨迹**而不是**可编辑的计划**。

### 6.2 用户体验

```
┌─────────────────────────────────────────┐
│ 🤖 SuperManus                            │
│                                         │
│ ▸ 步骤 1  webSearch                     │
│    思考：需要先查一下最新的行业数据……      │
│    结果：找到 5 条结果……                 │
│ ▸ 步骤 2  scrapeWebPage                  │
│    结果：抓取正文 3200 字……              │
│ ▸ 步骤 3  回答                           │
│                                         │
│ 最终交付：一份带数据来源的分析报告         │
└─────────────────────────────────────────┘
```

- 会话列表在左侧，可新建 / 删除。
- 每条助手消息携带**可折叠的步骤时间线**（步骤序号、名称、思考内容、工具结果）。
- 流式实时推送，无需等待全部执行结束。

### 6.3 工具清单（当前实际可用的 6 个）

| 工具 | 能力 | 产物位置 | 权限约束 |
|------|------|---------|---------|
| `readFile` / `writeFile` | 读写工作目录下的文本文件 | `<work-dir>/file/` | 仅沙箱目录内，文件名已做路径穿越防护 |
| `generatePDF` | 生成含中文的 PDF | `<work-dir>/pdf/` | 同上 |
| `downloadResource` | 下载外部 URL 资源 | `<work-dir>/download/` | 仅 http/https |
| `scrapeWebPage` | 抓取网页正文（jsoup） | 返回文本 | 超时 15s |
| `searchWeb` | 网页搜索（SearchAPI / Bing） | 返回文本 | **需配置 API Key，否则返回不可用提示** |
| `doTerminate` | 主动结束任务 | — | 模型自行调用 |

> **注意**：知识库检索工具（`knowledge_search` / `document_read`）**尚未实现**。
> 这意味着当前智能体**无法检索企业知识库**，只能使用外部网络与本地文件系统——
> 这是「超级智能体」区别于「智能问答」的核心能力，也是当前最需要补齐的缺口（见 §14 P0-1）。

### 6.4 权限约束

- 智能体入口统一挂 `@RequirePermission(resource = "AGENT", action = READ)`，与角色体系一致。
- **但工具层目前没有独立的权限网关**：所有工具对所有可进入智能体的用户一视同仁。
  文件工具受限于服务端工作目录沙箱，但**没有按用户隔离的工作目录**。

### 6.5 目标形态与差距

| 能力 | 目标 | 现状 | 差距 |
|------|------|------|------|
| 计划先行 | 生成 JSON 计划，用户可编辑 | 无计划对象 | 🔴 大 |
| 知识库可检索 | `knowledge_search` / `document_read` | 工具不存在 | 🔴 大 |
| 人在回路 | 写操作暂停等待确认 | 无 | 🔴 大 |
| 执行可干预 | 暂停 / 跳过 / 改单步 | 无 | 🟡 中 |
| 产物可取回 | PDF / 文件回传前端下载 | 产物落在服务端目录 | 🔴 大 |
| 步骤可审计 | 任务级持久化与审计 | 仅会话内 JSONB | 🟡 中 |
| 成本可控 | 分级模型路由 | 全程 qwen-plus | 🟡 中 |

## 七、权限体系

### 7.1 4 个角色

| 角色 | 谁能当 | 能做什么 |
|------|--------|---------|
| **管理员 ADMIN** | IT / 知识负责人（1–2 人） | 全部权限 + 用户管理 + 文档授权 + 审计查询 |
| **编辑者 EDITOR** | 各部门骨干（5–10 人） | 上传 / 编辑 / 删除文档，使用 SuperAgent |
| **查看者 VIEWER** | 全体员工 | 只读授权文档、基础问答 |
| **访客 GUEST** | 外包 / 临时人员 | 仅看公开文档 |

### 7.2 3 级密级

| 密级 | 标识 | 谁能看 |
|------|------|--------|
| **公开 PUBLIC** | 🟢 | 所有人（含访客） |
| **内部 INTERNAL** | 🔵 | 仅正式员工（管理员 / 编辑者 / 查看者） |
| **机密 CONFIDENTIAL** | 🔴 | 仅管理员 + 被单独授权的用户（编辑者当前**不可**访问） |

### 7.3 实际生效的权限矩阵

以下矩阵是**代码最终效果**（四套判定路径的并集），也是当前最需要收敛的地方：

| 角色 | 🟢 公开 | 🔵 内部 | 🔴 机密 | 写操作（≤内部） | 用户管理 | 文档授权 |
|------|---------|---------|---------|----------------|---------|---------|
| **管理员** | 读写删 | 读写删 | 读写删 | ✅ | ✅ | ✅ |
| **编辑者** | 读写 | 读写 | ❌ | ✅ 公开/内部，❌ 机密 | ❌ | ❌ |
| **查看者** | 只读 | 只读 | ❌ | ❌ | ❌ | ❌ |
| **访客** | 只读 | ❌ | ❌ | ❌ | ❌ | ❌ |

**文档级授权（`doc_permissions`）可突破密级限制**：被单独授权的用户可以读取该文档，
无论密级与角色；`WRITE` 授权额外赋予写权限，但**只对管理员与编辑者生效**（只读角色永不可写）。

> ⚠️ **一致性问题**：权限判定当前分散在 4 处且结论不一致——
> 权限注解切面允许「编辑者读机密」，而访问校验器 / 向量过滤器 / 列表 SQL 均拒绝。
> 对外表现为「编辑者读不到机密」，但注解口径与实际行为相反，属于必须收敛的技术债（见 §14 P0-2）。

### 7.4 校验流程

```
请求到达
  → JWT 过滤器解析 token（userId / username / role / department）
  → @RequirePermission 切面：ADMIN 直通 → adminOnly 校验 → 角色×密级×操作 判定
  → 资源级校验（文档）：角色密级 或 文档级授权
  → 拒绝时写一条 DENIED 审计日志
  → 通过后放行
```

### 8.1 已覆盖的操作

|------|------|---------|
| 上传文档 | DOCUMENT | Service 层 |
| 删除文档 | DOCUMENT | Service 层 |
| 创建 / 修改 / 删除用户 | USER | Controller 层（**待下沉**） |

记录字段：操作人（ID + 用户名）、操作类型、资源、结果（成功/失败）、IP、时间、详情（JSONB，含失败原因）。

### 8.2 未覆盖（合规缺口）

- ❌ **登录 / 登出**未记录——无法回答「谁在什么时候登录过系统」。
- ❌ **文档查看 / 下载 / 分块阅读**未记录——无法回答「谁看过这份机密文档」。
- ❌ **问答与智能体调用**未记录——无法追溯 AI 回答的输入与使用者。
- ❌ 无异常行为检测（高频访问、异常时段、批量访问机密文档）。

> 企业场景下，「谁在什么时候看了什么文档」是 PRD 第一版就写下的目标，当前**尚未达成**——
> 审计目前只覆盖写操作与权限变更。

## 十四、下一步优化方向

### P0 — 阻塞产品价值，必须先做

**P0-1　超级智能体接入知识库（最大缺口）**
- 现状：智能体 6 个工具全是网络 / 文件类，**无法检索企业知识库**，与「智能问答」形成的能力断层。
- 方案：新增 `knowledge_search` / `document_read` 两个 `@Tool`，内部复用 `RagRetriever` 与 `DocumentAccessChecker`；过滤表达式沿用 `DocumentAccessFilter`，保证与问答链路同一套权限语义。
- 验收：智能体回答中出现企业文档引用，且引用可跳转；无权文档在工具层即被拒绝。

**P0-2　权限规则收敛为单一事实源**
- 现状：判定分散在 `PermissionService`（注解口径）、`DocumentAccessChecker`（文档口径）、`DocumentAccessFilter`（向量口径）、`DocumentRepository` 原生 SQL（列表口径）四处，结论不一致（编辑者能否读机密，四处给出两种答案）。
- 方案：抽取 `PermissionPolicy`（角色 × 密级 × 操作 → 判定），四处全部改为调用它；列表 SQL 改为 JPQL / Criteria Specification，避免原生 SQL 复制规则。
- 验收：权限矩阵用一张表格 + 一份单元测试锁定；任意一处改动必测。

**P0-3　审计补齐读操作**
- 现状：只看得到写操作与权限变更，看不到「谁看了什么」。
- 方案：为登录 / 登出 / 文档详情 / 分块阅读 / 问答 / 智能体调用补 `@AuditLog`；审计注解从 Controller 下沉到 Service。
- 验收：审计页能按用户 + 时间 + 资源类型回答合规问题。

**P0-4　智能体产物可交付**
- 现状：PDF 与文件落在服务端工作目录，用户拿不到，「生成报告」的价值闭环断掉。
- 方案：产物写入 `data/agent/output/{conversationId}/`，通过受权限校验的下载接口回传前端；工具返回值带产物路径。
- 验收：前端可一键下载生成的 PDF / Markdown。

**P0-5　密钥与部署基线**
- 现状：本地 dev 配置持有真实密钥（未入库，但易误提交）；生产 `JWT_SECRET` 有兜底默认值；无 Compose 编排。
- 方案：生产 profile 对关键密钥做**启动即校验**（缺失则拒绝启动）；提供 `.env.example` + `docker-compose.yml`（postgres+pgvector / backend / frontend+nginx）。
- 验收：一条命令拉起全栈；无默认密钥可通过启动。
